# Установка сервера на VPS через MobaXterm

Инструкция рассчитана на VPS с Ubuntu 22.04+ или Debian 12+, где уже могут работать сайт на nginx и боты. Subly их не трогает: сервер слушает только `127.0.0.1:8090`, наружу его отдаёт nginx по отдельному поддомену.

Займёт 15–20 минут, из них большая часть — ожидание DNS.

## Что понадобится

- VPS с доступом root по SSH (IP-адрес, логин и пароль или ключ от хостера);
- домен `antonshkel.ru` и доступ к его DNS (панель регистратора или хостера);
- [MobaXterm](https://mobaxterm.mobatek.net/download.html) — бесплатной Home Edition достаточно;
- 1 ГБ свободной памяти и 2 ГБ диска на VPS.

## Шаг 1. DNS: поддомен для Subly

В панели, где настроен DNS домена, добавьте запись:

| Тип | Имя | Значение | TTL |
|---|---|---|---|
| A | `subly` | IP вашего VPS | 3600 (или по умолчанию) |

Запись начнёт работать через 15–60 минут. Пока она расходится, делаем остальное.

## Шаг 2. Подключиться к серверу в MobaXterm

1. Запустите MobaXterm → кнопка **Session** (слева сверху) → **SSH**.
2. **Remote host**: IP сервера. Отметьте **Specify username** и впишите `root`. **Port**: `22` (или тот, что дал хостер).
3. Если вход по ключу: вкладка **Advanced SSH settings** → **Use private key** → выберите файл ключа.
4. **OK**. При первом входе MobaXterm спросит пароль и предложит сохранить его — можно согласиться.

Откроется чёрное окно терминала. Слева — панель SFTP с файлами сервера: через неё можно перетаскивать файлы мышкой, она пригодится для резервных копий.

> Вставить текст в терминал MobaXterm — правой кнопкой мыши или `Shift+Insert`. `Ctrl+V` в терминале не работает.

## Шаг 3. Скачать Subly и запустить установку

Вставьте по очереди:

```bash
apt-get update && apt-get install -y git
cd /root
git clone https://github.com/antonshkelll/Subly.git
cd Subly
sudo bash deploy/setup.sh
```

Скрипт спросит:

1. **Почту администратора** — ту, на которую вы потом зарегистрируетесь в приложении. С ней откроется админка.
2. **ЮKassa shopId и секретный ключ** — можно нажать Enter и подключить позже (шаг 6).

Дальше он сам:

- поставит Docker, nginx и certbot, если их нет;
- создаст папку `/opt/subly` и файл настроек `.env` со случайными паролями;
- скачает последнюю версию сервера из GitHub Releases (собирать на VPS ничего не нужно);
- запустит PostgreSQL и сервер в контейнерах и дождётся ответа `/health`;
- добавит сайт `subly.antonshkel.ru` в nginx;
- выпустит SSL-сертификат, если DNS уже работает.

В конце появится «Готово» и адреса сайта и админки.

## Шаг 4. SSL, если DNS ещё не обновился

Если скрипт написал «Домен пока не указывает на этот сервер», подождите 15–60 минут и выполните:

```bash
cd /root/Subly
sudo bash deploy/setup.sh --ssl
```

Проверка: откройте в браузере https://subly.antonshkel.ru — должен открыться лендинг с замком в адресной строке.

## Шаг 5. Первый вход

1. Установите APK на телефон: https://github.com/antonshkelll/Subly/releases/latest/download/subly.apk
2. Зарегистрируйтесь на почту администратора.
3. Откройте https://subly.antonshkel.ru/admin и войдите с той же почтой и паролем. Там видны пользователи, подписки, платежи и регистрации по дням.

## Шаг 6. Подключить ЮKassa

1. Зарегистрируйтесь на [yookassa.ru](https://yookassa.ru). Для приёма платежей нужен статус самозанятого или ИП. Для проверки хватит **тестового магазина**: он создаётся сразу, деньги не списываются.
2. В личном кабинете: **Интеграция → Ключи API** → выпустите секретный ключ. Там же виден `shopId`.
3. **Интеграция → HTTP-уведомления** → URL: `https://subly.antonshkel.ru/api/billing/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.
4. На сервере:

   ```bash
   cd /root/Subly
   sudo bash deploy/setup.sh --reconfigure
   ```

   Введите shopId и ключ. Сервер перезапустится.

5. В приложении: Профиль → Subly Pro → Оплатить. В тестовом магазине используйте тестовую карту из [документации ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing): номера карт для успешной и отклонённой оплаты перечислены там, срок действия — любой в будущем.

> Самозанятым ЮKassa умеет сама отправлять чеки в «Мой налог» — включите это в настройках магазина, чтобы не формировать чеки вручную.

## Обновление

Когда в репозитории выходит новая версия (новый тег `v…` → релиз):

```bash
cd /root/Subly
git pull
sudo bash deploy/setup.sh --update
```

Скрипт скачает новый jar, перезапустит сервер и сохранит прошлую версию для отката.

## Команды

| Команда | Что делает |
|---|---|
| `sudo bash deploy/setup.sh` | Первая установка |
| `sudo bash deploy/setup.sh --update` | Обновить сервер до последнего релиза |
| `sudo bash deploy/setup.sh --ssl` | Выпустить SSL, когда заработал DNS |
| `sudo bash deploy/setup.sh --reconfigure` | Поменять почту админа и ключи ЮKassa |
| `sudo bash deploy/setup.sh --status` | Состояние контейнеров и ответ `/health` |
| `sudo bash deploy/setup.sh --logs` | Журнал сервера в реальном времени (выход — `Ctrl+C`) |
| `sudo bash deploy/setup.sh --backup` | Копия базы в `/opt/subly/backups` |
| `sudo bash deploy/setup.sh --restart` | Перезапустить сервер |

Резервную копию удобно скачать на компьютер через панель SFTP слева в MobaXterm: откройте `/opt/subly/backups` и перетащите файл на рабочий стол.

## Что где лежит

| Путь | Что это |
|---|---|
| `/opt/subly/.env` | Настройки и ключи (права 600, только root) |
| `/opt/subly/subly-server.jar` | Сервер; `.prev` — прошлая версия |
| `/opt/subly/pgdata` | Файлы базы PostgreSQL |
| `/opt/subly/backups` | Резервные копии |
| `/etc/nginx/sites-available/subly.conf` | Сайт в nginx (certbot дописывает туда SSL) |
| `/var/log/nginx/subly.access.log` | Журнал запросов |

## Если что-то не работает

- **`502 Bad Gateway` на сайте** — сервер не запущен: `sudo bash deploy/setup.sh --status`, затем `--logs`.
- **Приложение пишет «Нет связи с сервером»** — проверьте, что https://subly.antonshkel.ru/health открывается в браузере телефона и отвечает `{"status":"ok"}`.
- **certbot не выпускает сертификат** — DNS ещё не обновился (`ping subly.antonshkel.ru` должен показать IP сервера) или порт 80 закрыт файрволом: `ufw allow 80,443/tcp`.
- **Оплата прошла, а Pro не включился** — в приложении Профиль → «Проверить оплату». Сервер сам спросит статус у ЮKassa, даже если вебхук не дошёл.
- **Мало памяти на VPS** — сервер ограничен 256 МБ (`-Xmx256m` в `docker-compose.yml`), PostgreSQL занимает ещё ~50 МБ.
